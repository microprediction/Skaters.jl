# Porting map: Python skaters -> Julia (Skaters.jl)

This package is a port of the Python reference (microprediction/skaters).
One rule governs everything: the parity gate. No module ships without
passing the pinned parity vectors at 1e-6.

## The parity gate

`parity/vectors.json` is generated by the Python reference and pinned to a
specific commit (recorded below). The gate replays every implemented
scenario through the Julia implementation and requires agreement to 1e-6:

```
julia --project=. test/parity.jl      # must print PARITY OK
```

Never commit red. The script runs from the repo root with the project
active. It parses the vectors with JSON.jl and compares the seven probes
(mean, std, logpdf@0.3, cdf@0.3, quantile@0.1, quantile@0.9, crps@0.3) for
every post-burn-in step and horizon of every scenario.

Current status: 75 scenarios plus the periodicity and covariance blocks,
145978 probe values, PARITY OK. The registry must cover every scenario the
reference wrote; the gate fails on any it does not.

## The other three gates

Beyond parity, three more suites run (all four together via `Pkg.test()`
or `julia --project=. test/runtests.jl`):

- `test/quantile_contract.jl`: the shared cross-language inverse-CDF
  contract. `parity/quantile_contract.json` is copied verbatim from the
  reference (its `parity/QUANTILE_CONTRACT.md` states the contract in
  words) and holds 64 cases that the Python, JavaScript and Rust runners
  also execute: `expected`/`atol` goldens, `lower`/`upper` intervals and
  `cdf_tol` round-trips. The fixture has one tolerance key, `atol`, and
  this runner uses it unchanged. The small extra assertions of the Python
  runner are mirrored too: tiny spread preserved, `max_iter` of 0 and 1,
  `tol` of 0 and -1, explicit failure on variance overflow. The
  reference's unit-scale CDF call count (36) is pinned through the budget
  instead of a counting subclass: 34 bisections reproduce the default
  answer at p = 0.9 and 33 do not.
- `test/robustness.jl`: adversarial streams through `laplace(1)`:
  constant series, lattice/repeats, a 1e9 monster spike with a
  post-recovery alarm-rate assertion (< 6% at a ~1e-2 two-sided
  threshold), an extreme finite 1e300 tick, scale collapse and recovery,
  vol whiplash on a trend, and a 3000-tick soak that must activate the
  GPD splice. Well-formedness is asserted at checkpoints: logpdf not NaN,
  cdf in [0,1] and monotone over probes, five ordered finite quantiles.
  The RNG is a deterministic UInt32 LCG plus Box-Muller, the same
  generator as the JS gate; Julia's default RNG is never used.
- `test/contract.jl`: bitwise determinism (two independently built
  skaters, probe streams compared through `reinterpret(UInt64, x)`) and
  checkpoint-resume equivalence (state serialized mid-stream with
  `Serialization`, resumed by a freshly built skater; the resumed probe
  stream must match the uninterrupted run bit for bit). Also covered for
  `adaptive_search` across an expansion boundary, which is why its state
  holds recipes and plain data only.

The adaptive search carries one deliberate departure, shared with the R
port: the Python reference stores live skater callables in the state,
while this port stores only recipes and plain data, rebuilding candidate
skaters on demand through a per-instance memo. Rebuilding is
deterministic, so values match the reference exactly (the
`search_default` parity scenario) and the state survives `Serialization`
round-trips (the resume contract). Two Python orderings are semantic and
preserved: expansion ranks `(score, index)` tuples in reverse (score
descending, then index descending) and pruning removes the first argmin;
the scoring loss is logpdf clamped to [-20, 20], with the lower clamp
also catching NaN.

## Two traps carried over from the R and Rust ports

CPython 3.12+ `sum()` is Neumaier-compensated. The Python source uses
`sum()` for Dist normalisation, moments, log-sum-exp and several dot
products. Julia's built-in `sum` uses pairwise summation, which differs.
`src/mathx.jl` implements `fsum` (Neumaier) and it is used exactly where
Python spells `sum()`. Sequential `+=` accumulators in Python (pdf, cdf,
crps, the matrix helpers, the GARCH grid NLL) stay sequential here.

Python `dict` insertion order is semantic in `sticky`: the atom selection
is a stable sort by weight, so ties break by first-seen order. The value
table is kept as parallel insertion-ordered vectors (`vals`, `wts`) and
the top-atom selection uses a stable `MergeSort`.

## Numerics

Float math is IEEE f64 throughout. `erf` and `erfc` come straight from the
openlibm that Julia's Base math already bundles, reached by `ccall` (no
extra package). openlibm's `erf` matches CPython's own `m_erf` to about
1e-16, far inside the 1e-6 gate. One place used to amplify that last
bit: a `SplicedDist` quantile in the deep tail bisected the body's
0.5(1 + erf) cdf at p near 1e-12, where erf's last bit sets a plateau. As
in the reference (skaters 0ad69a5), below 1e-8 body tail mass the quantile
is now solved on erfc sums (`_body_tail_quantile` in `src/tails.jl`), which
keep relative precision, so the answer is fixed by `tol` alone. openlibm's
`erfc` is fdlibm's, so no extra erfc port is needed. The Acklam inverse-normal quantile is
ported verbatim from tails.py, including the single Halley polish step.

State is plain nested `Dict{String,Any}` (and plain vectors) so it stays
trivially serializable. `Dist` is an immutable struct of `(w, m, s)`
tuples; `SplicedDist` is a small mutable struct that memoizes its quantile
grid. One caveat found while writing the contract suite: `SplicedDist`
does reach state after the tail warm-up, because `parade` buffers the
dists it returned (its `pending` list). That is fine for `Serialization`
(the struct round-trips exactly), but any structural state comparison
must compare it field by field rather than by identity; the contract
suite's `deepeq` does exactly that.

## Canonical state (cross-language checkpoints)

State uses the reference's canonical layout (skaters docs/STATE.md,
skaters#394), so a checkpoint written by Python, JS or this port resumes
in any of them. `state_to_json(state)` returns the plain image (every
`Dist` as `{"components": [[w, mean, std], ...]}`, every `SplicedDist` as
`{"spliced": true, "body": ..., "t_lo": ..., ...}`, tuples as lists) and
throws `ArgumentError`, naming the path, on non-finite floats, non-string
keys, functions or any other object. `assert_plain_state` checks without
converting. `state_from_json` is the inverse: a components dict whose
weights already sum to one is kept bit for bit through `Dist(comps,
Val(:trusted))`, as the reference's `Dist.trusted`, and others are
normalised. A JSON array comes back as a `Vector{Float64}`, `Vector{Int}`,
`Vector{Union{Nothing,Float64}}` or `Vector{Any}`, and skaters read typed
vectors through `_fvec!`, `_ivec!` and `_ofvec!`, which convert a restored
vector in place, so any numeric array (ints included) is accepted.

Layout changes made here to match the reference: sticky keeps `counts`, a
list of `[value, weight]` pairs in first-seen order (was parallel
`vals`/`wts`); multiscale keys `phase`, `pending`, `latest` and `score` by
the stride's decimal string (was Int); the period detector keys `cross` by
the lag's decimal string (was a vector in lag order); granger keeps `pend`
as a queue of `[laplace predictives, learned predictives]` pairs, `cum` as
`cum[h][phase]` pairs and `z` as a list, the reference's k-general layout;
terminal_leaf_ensemble carries `adapt` (`nothing`, or the adaptive
temperature's object). That last one came with a port of the reference's
`adaptive_temperature` (with `temp_rho` and `temp_band`), which this port
lacked. Every older Julia checkpoint still resumes: each of those skaters
rewrites its part of an old state on its next step.

`test/state_resume.jl` is the gate. `parity/gen_state_vectors.py` writes
`parity/state_vectors.json`: Python checkpoints, through `state_to_json`, of
50 scenarios (every transform under conjugate, laplace in its variants
including gaps, repeats and k = 3, granger, flesaker, dantzig, search,
multiscale, parade, sticky, homogenize, residual_transform, the ensembles
and the leaves) at t = 60, 250 and 530, with the next 20 Python outputs. For
each checkpoint the test checks that Julia's own checkpoint has the same
layout (same keys and JSON kinds everywhere), that Julia resumed from
Python's checkpoint matches Python and a Julia run from scratch to 1e-6,
and that Julia's own JSON checkpoint resumes bit for bit. It also rewrites
states into the older Julia layouts and checks they resume bit for bit, and
runs the walker checks of the reference's `tests/test_state_json.py`. The
other direction is a script pair: `parity/write_julia_checkpoints.jl`
writes Julia checkpoints for every scenario and
`parity/check_julia_checkpoints.py` resumes them in Python against Python's
own continuation. The reference's mahalanobis, zbank and gpdtail are not
covered (leaving skaters, skaters#90), nor its conforming_leaf and
ensemble_leaf, which are outside its public API.

`dist_affine`, `dist_shift` and `dist_scale` on `SplicedDist` mirror the
reference's `SplicedDist` methods (skaters #358 and its follow-up). The
splice lives in the body's PIT space, so only the body moves; a negative
multiplier swaps the tails and negates the thresholds. Without them,
conjugating `laplace()` with standardize, garch, ema_transform,
ou_transform, seasonal_difference or seasonal_anchor threw a `MethodError`
once the GPD splice went live. `test/spliced_affine.jl` checks the change
of variables and runs each wrapper past the splice, `seasonal_scale`
included.

The transform surface matches the reference's `transform.py` and
`pushforward.py` def for def. `PushforwardDist` (`src/pushforward.jl`)
takes either a `(ys, zs)` table or the analytic `inv_fn`, `fwd_fn`,
`log_jacobian_fn`, `component_moments_fn` and `scaled_inv_fn`, with the
reference's table CRPS and quantile-quadrature CRPS. Python duck-types on a
`components` attribute; here `_components(d)` plays that part: a `Dist`'s
own components, a `PushforwardDist`'s moment-matched shim (Gauss-Hermite per
inner component, or one Gaussian fitted on the 257-point quantile grid),
and `nothing` for a `SplicedDist`. `dist_combine`, `sticky`, `_widen` and
the delta-method inverses read it, so stacking (power_transform around
yeo_johnson around laplace) and combining pushforwards behave as in Python.

Transforms that read components handle `SplicedDist` as in the reference's
bc67bd8. At horizons past the first, ema_transform, seasonal_difference and
seasonal_anchor widen the body through `_widen` and rebuild the
`SplicedDist` with the same thresholds, tail masses and GPD parameters.
power_transform, yeo_johnson and gaussianize emit the exact pushforward of
a `SplicedDist` through their inverse map: a table from `table_from_map`
over the window from `quantile(1e-6)` to `quantile(1 - 1e-6)`, padded by its
span on each side. Mixture outputs take the old code path unchanged, which
the parity gate confirms. gaussianize uses CPython's `NormalDist.inv_cdf`
(Wichura's AS241, ported term for term as `_nd_inv_cdf`), not the Acklam
quantile the tails use. `log_transform` and `flesaker` throw `ArgumentError`
where the reference raises `ValueError`.

`dist_affine`, `dist_shift` and `dist_scale` on `PushforwardDist` mirror
the reference's `PushforwardDist.affine`, `shift` and `scale` (skaters
branch fix/pushforward-affine): the law of a*Y + b stays a pushforward of
the same inner, with the table mapped and every analytic piece (inverse,
forward, log-Jacobian, component moments, scaled inverse) composed. A
negative multiplier reflects the inner through `dist_scale(inner, -1)` and
reverses the table so the map stays increasing. This lets standardize,
seasonal_scale and the other affine transforms wrap an exact yeo_johnson,
a log_transform or a spliced pushforward. `test/pushforward_affine.jl`
mirrors `tests/test_pushforward_affine.py`.

`test/spliced_nonaffine.jl` mirrors the reference's
`tests/test_spliced_nonaffine.py`. `test/transform_parity.jl` replays
`parity/transform_vectors.json`, written by `parity/gen_transform_vectors.py`
against the reference (run it with `PYTHONPATH` at the reference's `src`).
It covers seasonal_scale, every gaussianize guard and the smooth mode, the
exact flags, log_transform with either bound, stacked and combined
pushforwards, flesaker, and laplace's spliced predictive through every
component-reading transform. Every value holds at 1e-6, the spliced
cases included, since the deep-tail fix described under Numerics.

Everything in the reference's `__all__` is exported here except
`mahalanobis` and `zbank`, which are leaving skaters for a separate package
(skaters#90). `search` and `build` are the reference's names for
`adaptive_search` and `spec_build`, and both spellings work. `dantzig`
forwards its keywords to `search`. `Skater` is `Base.Callable`, since a
skater here is any callable `(y, state) -> (dists, state)`.

`to_json` and `from_json` are the reference's spec serialisation (spec.py),
not skater state: the reference has no state JSON. `to_json` writes compact
JSON byte-identical to Python's `json.dumps(spec, separators=(",", ":"))`.
Julia's `Dict` is unordered, so keys are written in the reference's
constructor order (op, alpha, d, window, k, skaters, floor, skater,
transform, then any others sorted), and floats in Python's `repr` spelling
(`1e-05`, `1.0`) through `_py_float`. `spec_name` now formats with
Python's `.6g` through the same helper, which fixes names like
`ema_t(1e-05)` that used to print as `ema_t(1.0e-5)`.

`residual_transform` and `homogenize` port their modules line for line,
including the bisection standard-normal quantile on a unit Gaussian `Dist`
(not the Acklam quantile the tails use) and the 32-point quantile grid
behind `mean`, `std` and `crps` of `CorrectedDist` and `HomogenizedDist`.
`ResidualDiagnostics` is a mutable struct. The reference's `update` and
`summary` methods are `Skaters.update!(d, z)` (not exported, the name is too
generic) and `summary(d)`, which returns the reference's dict.
`test/wave2_parity.jl` replays `parity/wave2_vectors.json`, written by
`parity/gen_wave2_vectors.py` against the reference. It covers every
residual model, homogenize under each coupling and with custom candidates,
homogenize and residual_transform around laplace (also on 700 steps, with
the splice live), dantzig and search, the candidate grid, the residual z
stream and diagnostics, and the spec round trips. All 34941 values hold at
1e-6.

## Refresh ritual

This port is faithful to skaters as of the pinned commit. To refresh:

1. In the Python repo: `PYTHONPATH=src python parity/gen_vectors.py`.
2. Copy `parity/vectors.json` here as `parity/vectors.json`, and
   `parity/quantile_contract.json` likewise.
3. Run the gate. Port whatever new or changed module makes it green.
4. Update the provenance commit below.

## Provenance

`parity/state_vectors.json` comes from `parity/gen_state_vectors.py` run
against skaters branch feat/canonical-state (080668b, skaters#394) with
fix/spliced-nonaffine (0ad69a5) merged in and bec9df0's `pushforward.py`
applied, so the reference has both the canonical layout and the numerics
the rest of the gate pins.
All other parity vectors come from one reference tree: skaters commit
`0ad69a5ff7cea3bc049b351d9a76d5f4c6be0afb` (branch fix/spliced-nonaffine,
with the deep-tail spliced quantile fix) plus the `src/skaters/pushforward.py`
change of `bec9df0c6c90a41d0be72a1290455721e9c8b770` (branch
fix/pushforward-affine, `PushforwardDist.affine`), applied on top.
`parity/vectors.json` is that tree's `parity/gen_vectors.py` output, and
`parity/quantile_contract.json` is unchanged from it.
`parity/transform_vectors.json` and `parity/wave2_vectors.json` come from
`parity/gen_transform_vectors.py` and `parity/gen_wave2_vectors.py` run
against it. The scale-relative `Dist.quantile` and the 2100 default budget
are mirrored in `dist_quantile(::Dist)` and forwarded by
`dist_quantile(::SplicedDist)`.
The robustness and contract suites mirror the R port
(`skaters-r/tests/robustness.R`, `tests/contract.R`) and the Rust crate
(`rust/tests/robustness.rs`), which in turn mirror the reference repo's
`parity/adversarial.mjs` and `tests/test_tails_robustness.py`.
